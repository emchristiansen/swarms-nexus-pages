Theseus private reports: privacy policy

Prepared October 4, 2026. The app is a personal tool operated for the owner of the Theseus agent system. Reporting remains switched off while setup is being completed. This policy describes the prepared app's data handling; it does not claim that the receiver is installed or that live consent or delivery has been tested.

Google data and permissions

The app requests exactly Gmail insertion (https://www.googleapis.com/auth/gmail.insert), OpenID (openid), and email identity (https://www.googleapis.com/auth/userinfo.email). It uses the returned identity claims to check that authorization belongs to the intended receiving account and OAuth client. It uses an access token to insert a report into that account's inbox, marked unread. The app does not request or use an API to read existing messages, delete messages, or send messages to other recipients.

Storage and retention

During consent, the app holds the authorization exchange, identity claims, access token, and temporary state in memory. An accepted refresh token is stored in 1Password and retrieved through SecretSpec when needed to request an access token. The OAuth client credentials are also supplied through SecretSpec. They remain under the owner's and authorized operators' credential custody; a shared host is not an isolation boundary between agents. Removing Google's access does not itself delete stored credentials.

To generate a report, the app starts a separate continuation of the calling agent's existing conversation. The agent's AI provider processes the available conversation context and resulting report; the app also reads the caller's local session record to prepare that continuation. This does not establish which exact transcript bytes the provider receives, caches, or retains.

Report text stays in the reporting process's memory during transport, then is stored by Gmail as a new inbox message. A delivery receipt can reveal a reporting identifier, delivery time, delivery result, and Google's stored message identifier. Gmail keeps the message until the account holder deletes it under Google's own retention rules. The app does not delete mailbox messages or automatically erase existing transcripts, receipts, backups, or stored credentials.

Who receives data

Google receives authorization requests and the reports inserted through Gmail. 1Password holds the stored refresh token. The reporting agent's AI provider and agent harness process report content before delivery. The workstation, provider records, and shared agent transcripts can expose report content or metadata; this app does not prove that no copies exist or hide the fact that a particular agent reported. The Google authorization grants insertion and identity checks; it does not grant the app access to the mailbox's existing contents.

Use of Google data

The prepared app uses Google identity and authorization data only to establish the intended receiving account and deliver reports there. It has no advertising, data resale, credit-scoring, or model-training feature. Its use of Google API data is limited to the reporting and account-checking functions described here. Theseus private reports' use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements: https://developers.google.com/terms/api-services-user-data-policy .

Visiting these pages

These static pages use GitHub Pages. GitHub records visitors' IP addresses for security. The pages include no sign-in, report-submission form, scripts, analytics, or embedded third-party content. Visiting them does not authorize Gmail access or turn on reporting. GitHub's own privacy practices apply to its hosting: https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement .

Stopping access and requesting help

The account holder can remove the app's access in their Google Account's third-party connections settings. Once Google's revocation has taken effect, the grant can no longer be used; it does not erase previously inserted messages or prove deletion of credentials or copies elsewhere. Credential removal and host cleanup are separate actions. If an interrupted consent attempt leaves revocation unconfirmed, the account holder may need to remove the grant directly in Google.
